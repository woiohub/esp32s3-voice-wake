# 上下位机接口设计

> 版本 v0.3 · 对应固件 fw 0.5.0 / 上位机 host v0.7.2
> 关联文档：`../README.md`（方案总览）、`02_项目计划.md`（任务分解）
>
> **本文是跨两端的协议总览。** 具体的实现细节请分别看：
> - 下位机：`../firmware/docs/01_接口设计.md`（设备收什么、回什么、状态机、NVS）
> - 上位机：`../host/docs/01_接口设计.md`（服务端实现、ACK 匹配、下发节奏、GUI 回调）

## 1. 系统拓扑与连接

```
┌─────────────────────────────┐          WiFi / TCP           ┌──────────────────────────────┐
│  下位机 ESP32-S3-CAM        │  ◄──────── 上行语音 PCM ─────── │  上位机 PC（Python）          │
│  · INMP441  (I2S 输入)      │  ──────── 下行 TTS PCM ───────► │  · TCP 服务端（监听）          │
│  · ESP-SR 唤醒词检测         │  ◄──────── 控制/配置 JSON ────► │  · STT → LLM → TTS 管线        │
│  · MAX98357 (I2S 输出)      │                                 │  · PySide6 GUI                 │
└─────────────────────────────┘                                 └──────────────────────────────┘
```

- **连接方向**：设备是 **TCP 客户端**，上位机是 **TCP 服务端**（监听固定端口）。设备上电后主动连接上位机，断开自动重连。这样上位机（PC）只需一个固定局域网 IP，设备侧配置简单。
- **默认端口**：`8888`（可通过配置修改）。
- **发现机制**：一期不做自动发现。上位机 IP 通过**蓝牙配网**（设备连不上 WiFi 时自动开 BLE 广播）
  或上位机下发写入设备 NVS。

## 2. 传输层

- 协议栈：`TCP`（可靠字节流）。
- 应用层帧协议：本文件定义的帧化协议（自带长度前缀 + CRC，解决粘包/半包）。
- 字节序：**多字节字段一律大端（Big-Endian）**。
- 保活：心跳 `HEARTBEAT` 每 3s 一次，超时 10s 判死并重连。

## 3. 帧格式（字节级）

| 偏移 | 字段 | 长度 | 说明 |
|-----|------|-----|------|
| 0 | MAGIC | 2 | 固定 `0xAA 0x55` |
| 2 | VERSION | 1 | 协议版本，当前 `0x01` |
| 3 | TYPE | 1 | 消息类型，见下表 |
| 4 | SEQ | 4 | 序号，大端 u32，每个方向独立递增 |
| 8 | TIMESTAMP_MS | 4 | 时间戳（毫秒），大端 u32 |
| 12 | PAYLOAD_LEN | 4 | 载荷长度 N，大端 u32 |
| 16 | PAYLOAD | N | 载荷（视 TYPE 而定） |
| 16+N | CRC16 | 2 | CCITT-FALSE（多项式 0x1021，初值 0xFFFF），覆盖 0..15+N 全部字节 |

**帧总长 = 18 + N 字节。**

### 消息类型 TYPE

| 值 | 名称 | 方向 | 载荷 |
|----|------|------|------|
| 0x01 | CONTROL | 双向 | UTF-8 JSON（见 §5） |
| 0x02 | AUDIO_UP | 设备→上位机 | 语音 PCM 子帧（见 §6） |
| 0x03 | AUDIO_DOWN | 上位机→设备 | TTS PCM 子帧（见 §6） |
| 0x04 | HEARTBEAT | 双向 | 空或 JSON `{"ts":...}` |
| 0x05 | ACK | 双向 | JSON 通用应答（见 §5.2） |

## 4. CRC16

- 算法：CCITT-FALSE（CRC-16/IBM），多项式 `0x1021`，初值 `0xFFFF`，不取反。
- 用于校验整帧；控制帧校验失败则丢弃并（可选）要求重传；音频帧校验失败直接丢弃（音频可丢）。

## 5. 控制帧（CONTROL）JSON 约定

控制帧载荷为 UTF-8 JSON 字符串（无 BOM，可含中文）。

### 5.1 请求格式

```json
{ "id": "8f14e45f", "cmd": "config.set", "params": { "volume": 60 } }
```

- `id`：请求标识（客户端生成，用于匹配应答）。
- `cmd`：命令名。
- `params`：命令参数。

### 5.2 应答格式

成功：

```json
{ "id": "8f14e45f", "cmd": "config.set", "code": 0, "result": { "volume": 60 } }
```

失败：

```json
{ "id": "8f14e45f", "cmd": "config.set", "code": 2002, "error": "invalid volume range" }
```

`ACK` 帧承载同构 JSON（`{id, code, error?}`），用于无返回值指令的确认。

### 5.3 命令清单

| cmd | 方向 | params | 说明 |
|-----|------|--------|------|
| `hello` | 设备→上位机 | `{"device":"esp32s3","fw":"0.5.0","audio":{"rate":16000,"bits":16,"ch":1},"mac":"28:84:85:45:7B:3C","rssi":-52,"wakeword":"wn9_hilexin","volume":60}` | 连接建立后上报设备信息（v0.7.1 起含 MAC/RSSI/唤醒词/音量，供设备页直接显示） |
| `config.get` | 双向 | `{}` | 读取配置，`result` 返回 `volume, wake_enable, ack_enable, wifi_ssid, host_ip, host_port` |
| `config.set` | 上位机→设备 | 见 §5.4 | 下发配置 |
| `wifi.set` | 上位机→设备 | `{"ssid":"...","password":"..."}` | 更新 WiFi 凭证（**500ms 后设备重启生效**） |
| `host.set` | 上位机→设备 | `{"ip":"192.168.1.10","port":8888}` | 上位机地址（**500ms 后设备重启生效**） |
| `volume.set` | 上位机→设备 | `{"volume":0..100}` | 音量（立即生效 + 写 NVS） |
| `wakeword.set` | 上位机→设备 | `{"enable":true}` | 仅启停唤醒。**不支持运行期换词**（模型在 flash 分区，需改 `CONFIG_VW_SR_WAKENET_NAME` 重烧） |
| `reboot` | 上位机→设备 | `{}` | 回 ACK 后重启 |
| `status.get` | 上位机→设备 | `{}` | `result` 返回 `fw, volume, wifi, prov, wake_enable, ack_enable, state`（`state`：0=IDLE 1=ACK_WAIT 2=CAPTURE 3=PLAYBACK） |
| `session.start` | 设备→上位机 | `{"session_id":123456,"need_ack":true}` | 开始一次语音会话；`need_ack=true` 表示设备在等"回复词"音频，收到并播完后才开始采集（v0.7.0） |
| `session.end` | 设备→上位机 | `{"session_id":123456,"reason":"vad"}` | 结束会话（`vad`=静音判定，`max`=超时，`nospeech`=唤醒后无人说话，`interrupt`=被打断） |

> `session_id` 是 **u32 数字**，不是字符串。

### 5.4 config.set 参数（可下发项）

```json
{
  "volume": 0,          // 0..100 播放音量
  "wake_enable": true,  // 是否启用唤醒
  "ack_enable": true,   // 唤醒后是否先播报回复词（播完再采集），v0.7.0
  "host": {"ip": "192.168.1.10", "port": 8888},
  "wifi": {"ssid": "xxx", "password": "xxx"}
}
```

> `ack_enable` 只控制**设备是否等待**回复词；回复词文本由上位机合成（`config.json → device.ack_text`），
> 不下发给设备。设备侧对应 NVS 键 `ack_en`。

#### 唤醒回复词时序（v0.7.0）

```
设备：唤醒命中 → session.start{need_ack:true} → APP_ACK_WAIT（最长 4s）
上位机：立即 TTS 合成 ack_text → AUDIO_DOWN(session_id, START..END)
设备：播放完毕（收到 END 帧并播完）→ 切到 APP_CAPTURE → 开始上行音频
上位机：正常 STT → LLM → TTS → 音频下发
```

未启用/合成失败时，上位机发一个**空 END 帧**，设备立刻进入采集（设备侧另有 4s 超时兜底）。

## 6. 音频帧（AUDIO_UP / AUDIO_DOWN）

音频参数统一：**16kHz / 16bit / 单声道 / 小端 PCM**。

> **下发节奏（必须遵守）**：AUDIO_DOWN 每帧 20ms，上位机必须按≈实时节奏发送
> （保持领先播放进度 100~200ms）。下位机播放队列仅 40 帧（≈800ms），
> 一次性灌入整段 TTS 会因队列满而丢帧，听感就是"10 秒的话 1 秒念完"。

载荷 = 音频子帧头 + 原始 PCM：

| 偏移 | 字段 | 长度 | 说明 |
|-----|------|-----|------|
| 0 | SESSION_ID | 4 | 会话 ID，大端 u32 |
| 4 | FLAGS | 1 | 标志位（见下） |
| 5 | PCM | N | 原始 PCM（每帧默认 320 样本 = 640 字节） |

FLAGS 位定义：

| 位 | 名称 | 方向 | 含义 |
|----|------|------|------|
| bit0 | START | 双 | 会话/播放开始（首帧） |
| bit1 | END | 双 | 会话结束（VAD 静音 / 播放结束，末帧） |
| bit2 | HAS_SPEECH | 上行 | 该帧含有效语音（供上位机 VAD 参考） |

- **上行**：设备唤醒后按 20ms 分帧边采边发；VAD 判定静音或达最大时长时，发 `FLAGS.END` 并结束会话。
- **下行**：上位机按 20ms 分帧下发；`START` 首帧后设备开始播放，`END` 末帧播放完。

## 7. 关键时序

### 7.1 唤醒 → 回复

```
设备                      上位机
 │── hello ────────────────►│
 │◄──────── 就绪（无音频）    │
 │  [唤醒词命中]              │
 │── session.start ────────►│
 │── AUDIO_UP(流式) ───────►│── STT
 │── AUDIO_UP(END) ───────►│── LLM 精简回复
 │◄── AUDIO_DOWN(流式) ────│── TTS
 │  [MAX98357 播放，AEC 使能] │
 │◄── session.end ─────────│
```

### 7.2 配置下发

```
上位机                      设备
 │── config.set(volume=60) ─►│  应用 + 写 NVS
 │◄── ACK code=0 ───────────│  回实际生效值
```

## 8. I2S 引脚与音频参数

### 8.1 引脚（推荐默认，**需按实际板型核对**）

| 信号 | 麦克风 INMP441 (I2S0-RX) | 功放 MAX98357A (I2S1-TX) |
|------|--------------------------|--------------------------|
| BCLK (SCK) | GPIO5 | GPIO16 |
| WS / LRC (LRCLK) | GPIO4 | GPIO15 |
| DIN (SD) | GPIO6（输入） | GPIO7（输出） |

其他：

- INMP441 `L/R` 脚 → 接 GND（选左声道）；`VDD` 3.3V。
- MAX98357A `GAIN` 脚 → 默认 12dB（接 GND）；`SD_MODE` 脚 → 接 3.3V（正常播放）。
- 引脚通过 `Kconfig.projbuild` 可配，正式接线前以目标板原理图为准。

### 8.2 音频参数

| 项 | 值 |
|----|----|
| 采样率 | 16000 Hz |
| 位深 | 线上/内存统一 16 bit；INMP441 侧按 32bit 槽读取后右移 16 位取高 16bit |
| 声道 | 单声道（AFE 输入为 2 通道交错 [mic, ref]） |
| 帧长 | 20ms = 320 样本 = 640 字节 |
| I2S 模式 | Standard Philips，无 MCLK（两块芯片均无需 MCLK） |
| RX 时钟 | 32bit 槽宽 / 单声道 → BCLK = 64×fS = 1.024 MHz（INMP441 手册硬性要求 fSCK=64×fWS） |
| TX 帧格式 | 16bit / 立体声，单声道样本复制到 L/R 两槽（适配 MAX98357A 任意 SD_MODE） |
| DMA | 环形缓冲，RX/TX 各 ≥ 4 × 20ms |

## 9. 错误码

| code | 含义 |
|------|------|
| 0 | 成功 |
| 1001 | 帧头/魔数错误 |
| 1002 | CRC 校验失败 |
| 2001 | 未知命令 |
| 2002 | 参数非法 |
| 3001 | WiFi 未连接 |
| 3002 | 未连接上位机 |
| 4001 | 音频繁忙（正在播放/采集） |
| 5001 | 内部错误 |

## 10. NVS 配置键

命名空间：**`vw`**（`firmware/components/vw_config/config_store.c`）

| 键 | 类型 | 默认值来源 | 说明 |
|----|------|-----------|------|
| `vol` | blob(u8) | `CONFIG_VW_DEFAULT_VOLUME` = 60 | 音量 0..100 |
| `wake_en` | blob(u8) | 1 | 唤醒开关 |
| `ack_en` | blob(u8) | 1 | 是否等回复词播完再采集（v0.7.0） |
| `wifi_ssid` | str(33) | `CONFIG_VW_DEFAULT_WIFI_SSID` | WiFi 名称 |
| `wifi_pass` | str(65) | `CONFIG_VW_DEFAULT_WIFI_PASS` | WiFi 密码 |
| `host_ip` | str(16) | `CONFIG_VW_DEFAULT_HOST_IP` | 上位机 IP |
| `host_port` | blob(u16) | `CONFIG_VW_TCP_PORT` = 8888 | 上位机端口 |

生效顺序：**先套 Kconfig 默认值，再用 NVS 里存在的键覆盖**。

> **没有 `wake_word` 键**：唤醒词来自编译期模型（`CONFIG_VW_SR_WAKENET_NAME`），
> 运行期不可改，因此不持久化。详见 `../firmware/docs/04_配置说明.md`。
