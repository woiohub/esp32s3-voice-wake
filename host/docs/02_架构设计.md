# 上位机架构设计（Python / PySide6）

> 适用版本：**host v0.7.2** · Python 3.10+ · PySide6 6.x
> 下位机侧同名文档：`../../firmware/docs/02_架构设计.md`

---

## 1. 定位与边界

上位机负责"大脑"：把设备送上来的语音变成文字、把文字变成回答、把回答变成语音送回设备。

| 负责 | 不负责 |
|---|---|
| STT（faster-whisper，本地） | 唤醒词检测（在下位机，必须离线） |
| LLM（GLM / Qwen，OpenAI 兼容接口） | 音频采集/播放（I2S 在 MCU 上） |
| TTS（Piper，本地） | 设备状态机（设备自己管） |
| 会话编排、ACK、下发节奏 | |
| GUI：会话/设备/模型/日志四页 | |

设计原则：

1. **业务层不依赖 GUI**。`pipeline` 与 `stt/llm/tts` 里没有任何 Qt import；
   需要通知界面时只调可选回调（为 `None` 则静默）。
2. **UI 线程不做阻塞事**。模型加载、网络请求一律丢到 `QThreadPool` 或 asyncio 线程。
3. **配置即文档**。所有可调项都在 `config.json`，首次启动自动生成模板。

### 2.1 依赖方向

```
main
 ├─► gui (pages/widgets → bridge → theme/icons/tasks)
```

`protocol` 是唯一与固件共享语义的模块（字节级对齐），改动必须两侧同步。

## 3. 线程模型

这是本项目最容易出问题的地方，约定如下：

| 执行体 | 跑什么 | 与 UI 的交互方式 |
|---|---|---|
| **Qt 主线程** | 所有控件操作、`MainWindow` 槽函数 | — |
| **asyncio 线程**（`threading.Thread(daemon=True)`） | TCP 服务、收帧、pipeline 协程、TTS/STT/LLM 的 `run_in_executor` | 通过 `bridge` 的 Signal emit（跨线程自动排队） |
| **QThreadPool**（`tasks.run_task`） | 模型加载、模型下载、试听合成、测试大模型 | 完成后发 Signal |

### 3.1 三条铁律

1. **任何耗时操作都必须走 `tasks.run_task` 或 asyncio**。在 UI 线程里 `stt.preload()`
   会直接把窗口卡住（首次加载 small 模型约 1.3s，Piper 约 3.6s）。
2. **`bridge` 里不允许碰控件**。它只负责 emit；`QueuedConnection` 保证槽函数在主线程执行。
3. **GUI → pipeline 的调用用 `asyncio.run_coroutine_threadsafe`**
   （`pipeline.submit_device_request`、`MainWindow._run`）。

### 3.2 为什么 asyncio 在独立线程

PySide6 的事件循环和 asyncio 的事件循环**不能互相嵌套**。把 asyncio 放到独立线程后：

- Qt 事件循环只管 UI，不被网络收发拖慢；
- GUI 线程通过 `server.loop` 句柄投递协程（线程安全）；
- 回调通过 Signal 回到 UI 线程，天然解耦。

## 4. 会话管线

```
AUDIO_UP ──► Session 累积 ──END──► _process()
                                    ├─ 音频校验（时长/是否全静音）
                                    ├─ STT（线程池）
                                    ├─ LLM（线程池）
                                    ├─ TTS（线程池）→ 重采样到 16k
                                    └─ _send_audio_frames()（实时节奏）
```

阶段与事件的对应关系见 `01_接口设计.md §6`。

### 4.1 分步失败定位

早期实现出错只报"处理失败（见日志）"，用户不知道卡在哪。现在每一步都用
`(cur, step)` 记录当前环节：

```python
step = "音频校验"; cur = "stt"
...
except Exception as exc:
    self._stage(cur, "failed")
    self._notify(f"{step} 失败：{brief}")     # brief = 异常消息首行
    self._error(0, f"{step} 失败：{brief}")
```

于是界面会显示 `STT（语音识别） 失败：找不到模型文件：...`，
而不是一句无语的"处理失败"。

### 4.2 音频时长校验

上行音频过短（< 0.2s）或全静音（RMS < 阈值）时直接跳过 STT，
报 `没有检测到有效语音`，省掉一次 1s+ 的推理。

## 5. 引擎封装

三个引擎的接口刻意保持同构，便于替换：

| 引擎 | 类 | 关键方法 | 阻塞 | 备注 |
|---|---|---|---|---|
| STT | `STTEngine` | `preload()`, `transcribe(pcm) -> (text, conf)` | 是 | 内部 `vad_filter=True` |
| LLM | `LLMClient` | `preload()`, `reply(text) -> str`, `reset()` | 是 | OpenAI 兼容，`_check_key()` 先自检 |
| TTS | `TTSEngine` | `preload()`, `synthesize(text) -> bytes` | 是 | 输出统一重采样到 16k |

### 5.1 STT

- 模型：faster-whisper（CTranslate2 格式），`REQUIRED_FILES = (model.bin, config.json, tokenizer.json)`。
- **默认不自动下载**：`stt.auto_download=false` 时找不到模型直接报错并提示
  「可点『一键下载模型』」，不会静默联网卡住。
- 环境变量必须在 **import faster_whisper 之前**设置（`stt.py` 顶部）：

  ```python
  os.environ.setdefault("HF_ENDPOINT", cfg.hf_endpoint)      # 国内用 hf-mirror.com
  os.environ.setdefault("HF_HUB_DISABLE_XET", "1")
  os.environ.setdefault("HF_HOME", <项目内路径>)
  ```

  > `HF_HUB_DISABLE_XET=1` 是为了绕开 xet 后端往 `C:\Users\<user>\.cache`
  > 写日志导致的 `os error 5 拒绝访问`。

### 5.2 LLM

- 两家都是 OpenAI 兼容接口，用同一个 `openai` 客户端，只换 `base_url` / `model`：

  | provider | base_url | 默认 model |
  |---|---|---|
  | `glm` | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
  | `qwen` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-turbo` |

- `_check_key()` 在发请求**之前**判空，避免"网络正常但 401"这种含糊错误。
- `_explain()` 把 401/403/429/超时/连接失败翻译成可执行建议。

### 5.3 TTS

- Piper 1.x：`PiperVoice.synthesize()` 返回 `AudioChunk.audio_int16_bytes`。
- **必须重采样**：huayan 模型输出 22050Hz，链路要 16000Hz。
  `resample_int16()` 用 numpy 做抗混叠低通 + 线性插值，无额外依赖。
- 忘了重采样会表现为"声音变调、语速变快"（22.05k 当 16k 播）。

## 6. GUI 结构

```
MainWindow
├─ 顶栏        logo · 设备状态胶囊 · 监听地址 · 复制/设置
├─ 左侧导航   72px：会话/设备/模型/日志（QToolButton#nav）
├─ 页面栈     QStackedWidget（设备页/模型页外套 QScrollArea）
├─ 右侧栏     280px 可折叠为 44px：连接/阶段/耗时/电平（Ctrl+R）
└─ 状态栏     模型灯 STT/LLM/TTS · 日志警告数 · 版本号
```

### 6.1 主题与样式约束

- **颜色/字号/间距只能来自 `theme.py` 的 token**，页面里不写颜色字面量。
- 需要按角色上色时用 `setProperty("role", "dim"|"title"|"small"|"error"...)`，由 QSS 统一。
- 深色主题下，**任何没被 QSS 覆盖的原生子控件都会露出系统浅色样式**（白色方块）。
  新增控件时务必检查：`objectName` 是否为空、QSS 有没有对应选择器、
  子控件（`::indicator`/`::handle`/`::add-page`）有没有漏写。

### 6.2 页面职责

| 页面 | 主要控件 | 依赖的回调 / 信号 |
|---|---|---|
| 会话 | 阶段条、对话流、文本输入、就绪清单 | `stage_changed` `transcript_ready` `reply_done` `level` |
| 设备 | 连接卡、AP 配网、下位机参数 | `device_state` `ack` |
| 模型 | STT/LLM/TTS 三卡、一键下载 | `model_status` |
| 日志 | 过滤/暂停/导出、错误码解释 | `log_line` |

### 6.3 信号桥（bridge）

12 个 Signal，全部由 `bridge.attach(pipeline, server)` 挂到业务回调上：

```python
stage_changed(str, str)      stage_timing(str, float)
transcript_ready(str, float) reply_done(str)      reply_chunk(str)
tts_started()                tts_finished()
interrupted()                level(float)
device_state(dict)           model_status(str, str, str)
error(int, str)              log_line(str, str, str)       ack(str, int, object)
```

`QtLogHandler` 把 `logging` 的日志也灌进 `log_line`，所以日志页能显示业务层日志，
而不只是 UI 自己的。

## 7. 配置与状态持久化

| 文件 | 内容 | 谁来写 |
|---|---|---|
| `config.json` | 音频/STT/LLM/TTS/网络/设备下发项 | 用户手改、GUI 保存（`save_config`） |
| `ui_state.json` | 窗口宽高、当前页、右侧栏折叠、主题 | `MainWindow.closeEvent`、`toggle_right` |

两个文件分开的原因：`config.json` 里有机密（`api_key`），
而 `ui_state.json` 是纯界面偏好，可以随便删；混在一起容易把 key 一键重置掉。

## 8. 扩展点

| 想加什么 | 改哪里 |
|---|---|
| 换 STT 引擎 | 新类实现 `preload` / `transcribe`，在 `main.py` 替换 `STTEngine(...)` |
| 接别家 LLM | `config.py::PROVIDER_PRESETS` 加一条（OpenAI 兼容即可） |
| 换 TTS | 实现 `preload` / `synthesize`（返回 16k int16 bytes） |
| 加 GUI 页面 | `pages/` 新建 Page，`main_window._build` 里加进 `QStackedWidget` + `_NAV` 加一项 |
| 加控制命令 | `device_page` emit `command` 信号 → `main_window._send_command` → `pipeline.request_device` |
| 加阶段指标 | `pipeline` 里调 `self._stage(...)`，阶段条会自动出现 |

## 9. 性能基线（本机实测，CPU）

| 环节 | 耗时 | 备注 |
|---|---|---|
| STT 模型加载（small/int8） | ~1.3s | 启动时一次 |
| STT 推理（1.5s 静音） | ~0.31s | |
| TTS 模型加载（huayan-medium） | ~3.6s | 启动时一次 |
| TTS 合成（29 字） | ~1.45s → 2.75s 音频 | 22050 → 16000 重采样后 |
| LLM（glm-4-flash） | 0.6~1.2s | 取决于网络 |
| 端到端（唤醒到出声） | 2.5~4s | 含 0.6s 回复词 |

> `small` 比 `tiny` 慢 3~5 倍。若端到端超过 5s，先把 `stt.model_size` 换成 `tiny` 试。

## 10. 设计取舍备忘

| 决策 | 选择 | 放弃的方案及原因 |
|---|---|---|
| GUI 框架 | PySide6 | Tkinter：样式能力太弱；Web：多一层进程通信 |
| 网络模型 | asyncio 服务端 | 线程 + socket：回调和超时管理更繁琐 |
| 业务与 UI 耦合 | 可选回调（`on_*`） | 直接 import GUI：业务层无法独立测试 |
| 模型分发 | 手动放置 + 一键下载 | 启动自动下载：无网时卡住、不可预期 |
| 音频压缩 | 裸 PCM | Opus：增加延迟与 CPU，局域网带宽足够 |
| 并发数 | 单设备、单会话 | 多设备：需要会话隔离与路由，当前场景不需要 |
