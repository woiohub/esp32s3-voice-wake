# 下位机配置说明（menuconfig / 分区 / NVS）

> 适用固件：**fw 0.5.0** · IDF v5.3.5

配置分三层，优先级从低到高：**Kconfig 默认值 → NVS 里已存在的键 → 运行期命令**。

```
sdkconfig.defaults / Kconfig.projbuild   ──编译期──►  CONFIG_VW_*
                                                      │
NVS namespace "vw"                       ──运行期──►  vw_config_t（覆盖默认值）
                                                      │
上位机 config.set / volume.set / ...      ──运行期──►  立即生效 + 写回 NVS
```

---

## 1. `idf.py menuconfig` 全部可调项

菜单位置：**Voice Wake System**（来自 `main/Kconfig.projbuild`，必须放在 `main/` 目录才生效）。

### 1.1 音频参数

| 配置项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `VW_SAMPLE_RATE` | 16000 | — | 采样率。**改这里必须同步改上位机 `audio.sample_rate`** |
| `VW_FRAME_MS` | 20 | — | 分帧时长。帧样本数 = rate×ms/1000 = 320 |
| `VW_DEFAULT_VOLUME` | 60 | 0..100 | 仅作为 NVS 为空时的默认音量 |

### 1.2 麦克风 INMP441（I2S0 RX）

| 配置项 | 默认 | 说明 |
|---|---|---|
| `VW_MIC_BCLK_GPIO` | 5 | SCK |
| `VW_MIC_WS_GPIO` | 4 | WS / LRCLK |
| `VW_MIC_DIN_GPIO` | 6 | SD（数据输入） |

**`VW_MIC_SLOT`**（三选一）：

| 选项 | 说明 |
|---|---|
| `VW_MIC_SLOT_AUTO`（默认） | 上电各采 32ms，按"等幅反号比例 / RMS"判断哪个声道是真实数据，必要时自动换槽并打印 `已自动切换到 x 声道` |
| `VW_MIC_SLOT_LEFT` | 强制左声道（`L/R` 接地） |
| `VW_MIC_SLOT_RIGHT` | 强制右声道（`L/R` 接 VDD） |

> 读错槽拿到的是 BCLK 串扰（数值恒为 ±21845 一类），表现为"有电平但唤醒永不触发"。
> 结构上没有把握时**保持 AUTO**。

### 1.3 功放 MAX98357A（I2S1 TX）

| 配置项 | 默认 | 说明 |
|---|---|---|
| `VW_AMP_BCLK_GPIO` | 16 | BCLK |
| `VW_AMP_LRC_GPIO` | 15 | LRC / WS |
| `VW_AMP_DOUT_GPIO` | 7 | DIN（数据输出） |

### 1.4 ESP-SR 唤醒引擎

| 配置项 | 默认 | 说明 |
|---|---|---|
| `VW_SR_MODEL_PARTITION` | `model` | 必须与 `partitions.csv` 的分区名一致；esp-sr 会 mmap 它 |
| `VW_SR_WAKENET_NAME` | `wn9_hilexin` | 唤醒词模型名。不存在时**回退到分区内第一个 `wn*`** 并打印全部可用模型，不会崩 |
| `VW_AFE_MODE` | `HIGH_PERF` | `HIGH_PERF` = AEC3 全带宽（需 PSRAM，效果好）；`LOW_COST` = 轻量 AEC |
| `VW_AFE_MEM` | `BALANCE` | `MORE_INTERNAL` / `BALANCE` / `MORE_PSRAM` |

常见模型名：

| 模型名 | 唤醒词 |
|---|---|
| `wn9_hilexin` | Hi 乐鑫 |
| `wn9_nihaoxiaozhi_tts` | 你好小智 |
| `wn9_xiaomeitongxue_tts` | 小美同学 |

> 换唤醒词 = 改这一项 + 重新 `idf.py flash`。**运行期不可换**（模型在 flash 分区里）。
> 想看板上到底有哪些模型：启动日志里 `srv:wake` 会打印 `可用模型: ...`。

### 1.5 通信

| 配置项 | 默认 | 说明 |
|---|---|---|
| `VW_TCP_PORT` | 8888 | 上位机监听端口，**必须与上位机 `network.port` 一致** |
| `VW_HEARTBEAT_PERIOD_S` | 3 | 心跳发送周期 |
| `VW_HEARTBEAT_TIMEOUT_S` | 12 | 超时判死（建议 ≥ 3 × 周期） |

### 1.6 出厂默认（NVS 为空时使用）

| 配置项 | 默认 | 说明 |
|---|---|---|
| `VW_DEFAULT_WIFI_SSID` | 空 | 空则上电进 AP 配网 |
| `VW_DEFAULT_WIFI_PASS` | 空 | |
| `VW_DEFAULT_HOST_IP` | 空 | 空则连不上上位机，需配网或下发 |

> 正式部署建议：**留空**，让设备进 AP 配网（`VoiceWake-XXXX`），
> 或由上位机设备页下发 `wifi.set` / `host.set`，写进 NVS 后重启生效。
> 把 SSID/密码硬编码进固件不适合仓库托管（会被提交进 git）。

## 2. `sdkconfig.defaults`（编译期硬约束）

`sdkconfig.defaults` 只在 **`sdkconfig` 不存在**时生效。
如果本地已有 `sdkconfig`，新增项**不会**自动套用——这就是"文档改了但行为没变"的常见原因。

### 2.1 关键项与理由

```ini
CONFIG_IDF_TARGET="esp32s3"

# 实测 Flash 16MB（启动日志 "Detected size(16384k)"）
CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y
CONFIG_PARTITION_TABLE_CUSTOM=y

# PSRAM：AFE 高性能模式强依赖；Quad 板必须改成 SPIRAM_MODE_QUAD
CONFIG_SPIRAM=y
CONFIG_SPIRAM_MODE_OCT=y
CONFIG_SPIRAM_SPEED_80M=y
CONFIG_SPIRAM_USE_MALLOC=y

# esp-sr 要求 data cache ≥ 64KB 且 cache line 64B
CONFIG_ESP32S3_DATA_CACHE_64KB=y
CONFIG_ESP32S3_DATA_CACHE_LINE_64B=y

# 模型走 flash 分区而不是编进固件
CONFIG_USE_AFE=y
CONFIG_AFE_INTERFACE_V1=y
CONFIG_MODEL_IN_FLASH=y
CONFIG_USE_WAKENET=y
CONFIG_SR_WN_WN9_HILEXIN=y
CONFIG_SR_MN_CN_NONE=y      # 不用命令词，srmodels.bin 从 ~3.9MB 降到 ~0.3MB
```

### 2.2 各项的"不改会怎样"

| 项 | 改错的后果 |
|---|---|
| `SPIRAM_MODE_OCT`（在 Quad 板上） | PSRAM 初始化失败 → 启动即复位 |
| `DATA_CACHE_64KB` | 编译告警 `Data cache recommends 64KB/64B`，WakeNet 变慢 |
| `MODEL_IN_FLASH` | 模型不产出 `srmodels.bin`，`esp_srmodel_init` 找不到模型 |
| `SR_MN_CN_NONE` | `srmodels.bin` 涨到 ~3.9MB，逼近 4MB 分区上限 |
| `FLASHSIZE_16MB` | 分区表偏移超出实际 flash → 烧录报错/运行异常 |

### 2.3 使 new defaults 生效

```bash
cd firmware
rm -f sdkconfig          # 或 idf.py fullclean
idf.py reconfigure
grep -E "SPIRAM_MODE|DATA_CACHE_64KB|FLASHSIZE" sdkconfig    # 核对
```

## 3. 分区表 `partitions.csv`

16MB flash 布局：

| Name | Type | SubType | Offset | Size | 说明 |
|---|---|---|---|---|---|
| `nvs` | data | nvs | 0x9000 | 0x6000 (24KB) | 配置持久化（namespace `vw`） |
| `phy_init` | data | phy | 0xF000 | 0x1000 (4KB) | RF 校准 |
| `factory` | app | factory | 0x10000 | 0x300000 (3MB) | 应用固件 |
| **`model`** | data | spiffs | 0x310000 | **0x400000 (4MB)** | **esp-sr 唤醒模型 `srmodels.bin`** |
| `ota_0` | app | ota_0 | 0x710000 | 0x300000 (3MB) | OTA 槽位 0 |
| `ota_1` | app | ota_1 | 0xA10000 | 0x300000 (3MB) | OTA 槽位 1 |
| `nvs_key` | data | nvs_keys | 0xD10000 | 0x1000 (4KB) | NVS 加密密钥 |

### 3.1 两条硬约束

1. **`model` 分区 ≥ `build/srmodels/srmodels.bin`**。
   分区小于 bin 体积时 esp-sr 只能 mmap 到部分数据，模型句柄解析到越界指针 →
   `LoadProhibited` 重启。本工程取 4MB，实际 bin 约 0.3MB（关掉 MultiNet 后）。
2. **改分区表必须 `erase-flash`**，偏移变了以后旧数据会落在错误位置。

```bash
idf.py -p COMx erase-flash
idf.py -p COMx flash
```

### 3.2 烧录方式

| 命令 | 是否烧 `model` 分区 |
|---|---|
| `idf.py flash` | ✅ 是（**必须用这个**） |
| `idf.py app-flash` | ❌ 否 → model 分区为空 → 启动崩溃 |

## 4. NVS 配置（运行期）

命名空间 `vw`，实现见 `components/vw_config/config_store.c`。

| 键 | 类型 | 默认（NVS 为空时） | 由谁写 |
|---|---|---|---|
| `vol` | blob(u8) | `CONFIG_VW_DEFAULT_VOLUME` | `volume.set` / `config.set` |
| `wake_en` | blob(u8) | 1 | `wakeword.set` / `config.set` |
| `ack_en` | blob(u8) | 1 | `config.set` |
| `wifi_ssid` | str | `CONFIG_VW_DEFAULT_WIFI_SSID` | `wifi.set` |
| `wifi_pass` | str | `CONFIG_VW_DEFAULT_WIFI_PASS` | `wifi.set` |
| `host_ip` | str | `CONFIG_VW_DEFAULT_HOST_IP` | `host.set` |
| `host_port` | blob(u16) | `CONFIG_VW_TCP_PORT` | `host.set` |

加载顺序：**先用 Kconfig 默认值填满 `vw_config_t`，再用 NVS 里存在的键覆盖**。
所以 NVS 为空时行为完全由 menuconfig 决定。

### 4.1 各种改法的生效时机

| 改动方式 | 生效时机 |
|---|---|
| `volume.set` / `config.set{volume}` | **立即**（且写 NVS） |
| `wakeword.set` / `config.set{wake_enable}` | **立即**（且写 NVS） |
| `config.set{ack_enable}` | **立即**（下一次唤醒生效） |
| `wifi.set` | 写 NVS 后 **500ms 自动重启** |
| `host.set` | 写 NVS 后 **500ms 自动重启** |
| `menuconfig` 改 Kconfig | 重新 `build + flash`，且 NVS 里已有的键会**覆盖**它 |

> 想让新的 Kconfig 默认值生效，要么擦掉 NVS（`idf.py erase-flash` 会连 NVS 一起擦），
> 要么用命令把对应值重新下发一遍。

### 4.2 手工清 NVS

```bash
# 整片擦除（连分区表、模型一起没了，需要重新 flash）
idf.py -p COMx erase-flash

# 只擦 NVS：用 esptool 按分区偏移擦
esptool.py -p COMx erase_region 0x9000 0x6000
```

## 5. 依赖与版本

| 项 | 版本 | 约束来源 |
|---|---|---|
| ESP-IDF | **v5.3.5** | `idf_component.yml` 要求 `idf >= 5.0` |
| esp-sr | **1.9.x** | `components/vw_wakeword/idf_component.yml`：`espressif/esp-sr: ^1.5.0` |
| 依赖解析结果 | 见 `dependencies.lock` | 提交进仓库，保证可复现 |

`managed_components/` 是组件管理器下载的产物，**不入库**（`.gitignore` 已排除），
首次 `idf.py build` 会自动拉取。

### 5.1 esp-sr 接口代际

| esp-sr 版本 | 接口 | 头文件 |
|---|---|---|
| 1.x | **AFE 接口** | `esp_afe_sr_iface.h` / `esp_afe_sr_models.h` / `esp_afe_config.h` |
| 2.x（未发布） | 统一 `esp_sr.h` | `esp_sr.h` |

本工程用的是 **1.x AFE 接口**。网上大量示例是 2.x 写法，照抄会报 `esp_sr.h: No such file`。

## 6. 配置检查清单（烧录前）

```bash
cd firmware
grep -E "CONFIG_VW_MIC_|CONFIG_VW_AMP_|CONFIG_VW_SR_WAKENET|CONFIG_VW_TCP_PORT" sdkconfig
grep -E "CONFIG_SPIRAM_MODE|CONFIG_ESP32S3_DATA_CACHE|CONFIG_ESPTOOLPY_FLASHSIZE" sdkconfig
ls -l build/srmodels/srmodels.bin          # 必须 < 4MB
grep -c "model," partitions.csv            # 确认 model 分区存在
```

对照表：

| 检查项 | 期望 |
|---|---|
| `VW_MIC_*_GPIO` | 与原理图一致，且未与摄像头/其他外设冲突 |
| `VW_MIC_SLOT` | 不确定就保留 AUTO |
| `VW_SR_WAKENET_NAME` | 与启动日志 `可用模型:` 里的某一项一致 |
| `VW_TCP_PORT` | 与上位机 `config.json → network.port` 相同 |
| PSRAM 模式 | 板子实际是 Quad 就必须改成 QUAD |
| `srmodels.bin` | < 4MB |
| 烧录命令 | `idf.py flash`（不是 `app-flash`） |
