# 下位机架构设计（ESP32-S3-CAM / ESP-IDF）

> 适用固件：**fw 0.5.0** · IDF v5.3.5 · esp-sr 1.9.x（AFE 接口）
> 上位机侧同名文档：`../../host/docs/02_架构设计.md`

---

## 1. 定位与约束

下位机只做"耳朵 + 嘴"：

| 只做 | 不做 |
|---|---|
| 本地离线唤醒词检测（不联网、不上传） | 语音识别（STT） |
| 唤醒后采集 PCM 并按 20ms 分帧上传 | 大模型推理 |
| 接收 PCM 并驱动功放播放 | 语音合成（TTS） |
| 端点检测、打断、参数持久化 | 任何需要联网的业务逻辑 |

这样切分的原因：唤醒必须离线且低延迟（AFE 跑在 S3 上约 30ms 内出结果），
而 STT/LLM/TTS 模型体积与算力都远超 MCU，放上位机才能换模型不改固件。

关键硬件约束：

- 只有 **1 路麦克风 + 1 路功放**，不支持全双工"边说边听"以外的并发。
- 唤醒模型常驻 flash `model` 分区并 mmap，**不占 RAM**。
- AFE 高性能模式强依赖 **PSRAM**（AEC3 全带宽）。

### 2.1 组件依赖（`CMakeLists.txt` 里的 REQUIRES）

| 组件 | REQUIRES | PRIV_REQUIRES | 职责一句话 |
|---|---|---|---|
| `vw_utils` | — | — | `VW_LOG_E(tag, code, ...)`、`vw_err_t`、`VW_FW_VERSION` |
| `vw_audio` | `driver` | — | INMP441 RX + MAX98357 TX 封装 |
| `vw_config` | — | `nvs_flash` | `vw_config_t` 读写 |
| `vw_wakeword` | `vw_utils` | `esp-sr` | 模型校验 + AFE 生命周期 |
| `vw_comm` | `vw_utils` | `esp_wifi esp_netif esp_event nvs_flash lwip esp_timer` | 帧协议 + TCP 重连 + WiFi/AP |
| `vw_voice` | `vw_audio vw_config vw_comm vw_wakeword vw_utils` | `json esp_timer` | 状态机 + 命令 + 端点 + 打断 |
| `main` | `vw_utils vw_audio vw_config vw_wakeword vw_voice` | — | 启动编排与故障保持 |

**依赖方向铁律**：`main → vw_voice → {驱动/服务/通信} → vw_utils`，底层不得反向依赖上层。
新增功能 = 新建组件并声明依赖，不需要动已有组件。

> `esp-sr` 通过 `components/vw_wakeword/idf_component.yml` 声明（`espressif/esp-sr: ^1.5.0`），
> 由 IDF 组件管理器下载到 `managed_components/`（该目录不入库，见 `.gitignore`）。

## 3. 任务模型

| 任务 | 栈 | 优先级 | 周期 | 职责 |
|---|---|---|---|---|
| `audio` | 8192 | 11 | 由 I2S DMA 阻塞读驱动（20ms/帧） | 读麦克风 → 喂 AFE → 状态机推进 → 上行发送 |
| `playback` | 4096 | 12 | 由队列取数据驱动 | 从播放队列取帧 → 音量缩放 → 写 I2S |
| `net_recv` | 4096 | 12 | 阻塞在 `recv()` | 收帧 → 解析 → 分发 `handle_control` / `on_audio_down` |
| `net_client` | 4096 | 10 | 重连循环 | 建连、心跳、断线重连 |

优先级设计：**`playback` ≥ `net_recv` > `audio` > `net_client`**。
播放不能被打断（否则卡顿听得出来），而 `audio` 有 DMA 缓冲兜底，短暂让出不影响采集。

### 3.1 并发与共享状态

| 共享物 | 保护方式 | 说明 |
|---|---|---|
| `g_state`（状态机） | `volatile`，只在 `audio` 任务里改写 | 其他任务只读 |
| `g_ref_buf`（AEC 参考） | `portMUX_TYPE` 自旋锁 | `audio` 读、`playback` 写，一次 memcpy |
| `g_play_q` | FreeRTOS 队列（深度 40） | 生产者 `net_recv`，消费者 `playback` |
| `g_cfg` | 单写者（`net_recv` 改、`audio`/`playback` 读） | 字段是 u8/bool/小字符串，撕裂风险可接受 |

> 用了 `portMUX_TYPE` 而不是 `taskENTER_CRITICAL()` 无参形式——后者在 IDF 5.x
> 需要自旋锁参数，写成无参会编译失败。

## 4. 数据流

### 4.1 上行（麦克风 → 网络）

```
I2S0 DMA ──(32bit 槽, 320 帧)──► audio_i2s_read() ──► >>16 转 int16
                                                        │
                    ┌───────────────────────────────────┤
                    ▼                                   ▼
        audio_i2s_check_frame()                wakeword_feed(mic, ref)
        （静止线/串扰/正常）                     （AEC + WakeNet + VAD）
                    │                                   │
                    │ 无效 → 限频告警                    │ wake_detected / vad
                    └──────────────► 状态机 ◄───────────┘
                                       │
                         APP_CAPTURE   │  net_client_send_audio(sid, flags, pcm)
                                       ▼
                                  TCP → 上位机
```

### 4.2 下行（网络 → 功放）

```
TCP ──► vw_parser_feed() ──► AUDIO_DOWN ──► on_audio_down()
                                               │ 拆出 session_id / flags / PCM
                                               ▼
                                        xQueueSend(g_play_q, 10ms 超时)
                                               │（满则限频告警 + 丢帧）
                                               ▼
                                    playback_task ──► apply_volume() ──► I2S1
                                               │              └─► set_play_ref()（AEC 参考）
                                               ▼
                                        AUDIO_FLAG_END → 状态切换
```

`set_play_ref()` 是 **barge-in 的关键**：把正在播放的 PCM 作为 AEC 参考喂回
`wakeword_feed(mic, ref)`，AEC 才能在扬声器轰鸣中听见人声。

## 5. 会话状态机

```
                    ┌────────────────────────────────────────────┐
                    │                                            │
                    ▼                                            │
   ┌──────────── APP_IDLE ◄──────────────────────────────┐       │
   │  唤醒命中 && 已连上位机                              │       │
   │  need_ack = ack_enable                              │ 播放完 + END
   ▼                                                     │       │
「ack_enable?」──否──────────────────────────────┐        │       │
   │是                                          │        │       │
   ▼                                            │        │       │
APP_ACK_WAIT ──4s 超时（ACK_TIMEOUT_MS）────────┤        │       │
   │  收到 END 且播完（playback_task 切换）      │        │       │
   └────────────────┬───────────────────────────┘        │       │
                    ▼                                     │       │
              APP_CAPTURE ──vad/max/nospeech──► session.end ──────┘
                    │
                    │ 收到 AUDIO_DOWN START
                    ▼
              APP_PLAYBACK ──END 且队列空──► APP_IDLE
                    │
                    │ 唤醒词命中（AEC）
                    └──► session.end{interrupt} ──► APP_CAPTURE（新一轮）
```

超时与阈值（`voice_service.c` 顶部宏）：

| 宏 | 值 | 含义 |
|---|---|---|
| `SILENCE_END_FRAMES` | 40（800ms） | 说过话后静音多久判定说完 |
| `MAX_CAPTURE_FRAMES` | 750（15s） | 单次发言硬上限 |
| `WAIT_SPEECH_FRAMES` | 150（3s） | 唤醒后一直没说话就结束（避免空录 15s） |
| `SPEECH_RMS_TH` | 300 | 去直流 RMS 能量兜底阈值 |
| `ACK_TIMEOUT_MS` | 4000 | 等回复词音频（含上位机首次合成） |
| `PLAY_QUEUE_DEPTH` | 40 | 播放抖动缓冲 ≈ 800ms |
| `PLAYBACK_IDLE_TIMEOUT_MS` | 10000 | 播放等待保护 |

### 5.1 为什么端点检测要"VAD + 能量"双判据

只用 AFE 的 VAD 时，现场出现过"每句话都录满 15 秒"（日志 `session end (max)`）：
噪声偏大或有直流偏置时 VAD 一直判为语音，会话就一路录到上限。
现在改成 `voiced = (VAD == SPEECH) || (去直流 RMS > 300)`，并加了 3s 无人说话超时。

> INMP441 有约 **-1900 的固定直流偏置**，必须先减均值再算 RMS，
> 否则"静音"的能量看起来也很大，阈值形同虚设。

## 6. 启动与故障保持

```
app_main()
 ├─ 打印复位原因（POWERON / PANIC / WDT / BROWNOUT…）+ free_heap
 ├─ 上次若是异常复位 → 额外 WARN 提示结合 Backtrace 定位
 ├─ config_store_init()   失败 → hold_on_error("config_store_init")
 ├─ audio_i2s_init()      失败 → hold_on_error("audio_i2s_init")
 └─ voice_service_init()  失败 → hold_on_error("voice_service_init")
        ├─ config_store_load(&g_cfg)
        ├─ xQueueCreate(40)
        ├─ wakeword_init(on_wake)      ← 内部 esp_srmodel_init("model")
        ├─ wifi_client_start(ssid, pass)
        ├─ net_client_start(host, port)
        ├─ xTaskCreate(audio, 8192, prio 11)
        └─ xTaskCreate(playback, 4096, prio 12)
```

**`hold_on_error()` 是刻意设计的**：早期版本用 `ESP_ERROR_CHECK` 包装，任一初始化失败就
`abort()` → panic → 芯片自动复位，串口只反复打印同一段启动日志，现场被冲掉。
现在改为**保持运行**：不重启，每 30s 打印一次"仍处于故障保持状态 + 失败阶段 + free_heap"，
并给出 4 条排查顺序（model 分区 / 分区体积 / PSRAM / data cache）。

## 7. 音频子系统要点

| 项 | 做法 | 为什么 |
|---|---|---|
| RX 槽宽 | **32 bit** + 单声道 + `slot_mask` | INMP441 要求 fSCK = 64×fWS；16bit 槽只有 32×fS |
| RX 数据转换 | `raw32 >> 16` | INMP441 24bit 有效数据在高位 |
| 声道选择 | `CONFIG_VW_MIC_SLOT` 三选一，默认**自动探测** | 读错槽拿到的是时钟串扰，表现为"有电平但永不唤醒" |
| TX 帧格式 | 16bit **立体声**，单声道复制到 L/R | MAX98357A 的 `SD_MODE` 接法决定取哪个槽，复制可通吃 |
| TX `auto_clear` | **true** | 默认 false 时 DMA 在无数据时循环重发最后一段 → 喇叭长鸣 |
| 线路自检 | `audio_i2s_check_frame()` → OK/STUCK/CROSSTALK | 让"麦克风没工作"一眼可辨，不被 `peak=21845` 误导 |

音量控制：MAX98357A 没有数字音量接口，音量在 `apply_volume()` 里做**软件缩放**
（`sample * volume / 100`，`volume>=100` 时直通不做乘法）。

## 8. 日志与错误码规范

- **TAG**：`<层>:<模块>` —— `main` / `drv:i2s` / `srv:wake` / `comm:net` / `app:voice`。
- **错误日志**：一律 `VW_LOG_E(tag, 错误码, "描述 %d", ...)`，自动加 `[0xXXXX:名称]` 前缀。
- **错误码分层**：`0x01xx` 通用 / `0x10xx` 驱动 / `0x20xx` 服务 / `0x30xx` 通信 / `0x40xx` 业务。
- **限频**：`mic peak`、`麦克风数据无效`、`唤醒已命中但未连接` 都做了 2~5s 限频，
  否则 20ms 一帧会把串口刷爆、把关键日志挤掉。

## 10. 设计取舍备忘

| 决策 | 选择 | 放弃的方案及原因 |
|---|---|---|
| 连接方向 | 设备作 TCP 客户端 | 设备作服务端：PC 侧要扫描发现、防火墙更麻烦 |
| 音频编码 | 裸 PCM 16k/16bit | Opus 压缩：省带宽但增加编码延迟与 CPU，局域网没必要 |
| 唤醒引擎 | esp-sr AFE（WakeNet + AEC） | 先用 VAD 触发再云端识别：不满足"本地离线唤醒"要求 |
| 端点检测 | VAD + 能量双判据 | 纯 VAD：噪声大时录满 15s（已踩过） |
| 音量 | 软件缩放 | 硬件数字音量：MAX98357A 无此接口 |
| 初始化失败 | 保持运行 + 周期日志 | `ESP_ERROR_CHECK`：会形成重启循环、冲掉现场 |
