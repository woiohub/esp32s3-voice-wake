# 下位机接口设计（ESP32-S3-CAM）

> 适用固件：**fw 0.5.0**（`components/vw_utils/include/vw_version.h`）
> 对应实现：`components/vw_comm/`（帧协议 / TCP / WiFi）、`components/vw_voice/`（会话与命令）
> 上位机侧同名文档：`../../host/docs/01_接口设计.md`

本文是**下位机视角**的接口契约：设备会发出什么、会接收什么、失败时回什么。
字段级实现位置都在文末的对照表里。

---

## 1. 系统拓扑与角色

```
┌──────────────────────────────┐        WiFi / TCP 长连接       ┌─────────────────────────┐
│ 下位机 ESP32-S3-CAM          │  ── 上行语音 PCM / 事件 JSON ──► │ 上位机 PC（Python）      │
│  INMP441  ── I2S0 RX         │  ◄── 下行 TTS PCM / 命令 JSON ── │  TCP 服务端（监听）      │
│  ESP-SR AFE（WakeNet+AEC+VAD）│                                │  STT → LLM → TTS 管线    │
│  MAX98357 ── I2S1 TX         │                                │  PySide6 GUI             │
└──────────────────────────────┘                                └─────────────────────────┘
```

| 项 | 约定 | 理由 |
|---|---|---|
| 角色 | 设备是 **TCP 客户端**，上位机是服务端 | PC 侧 IP 变动少、防火墙规则固定；设备侧只需记住一个 `host_ip:port` |
| 默认端口 | `8888`（`CONFIG_VW_TCP_PORT`） | 与上位机 `network.port` 必须一致 |
| 地址来源 | NVS `host_ip` / `host_port`，为空时回退到 `CONFIG_VW_DEFAULT_HOST_IP` | 首次用**蓝牙配网**或上位机下发写入 |
| 断线行为 | 自动重连（间隔 3s 起步），重连成功后**重新发 `hello`** | 上位机据此刷新设备页 |
| 并发连接 | 只维护 1 条连接 | 单麦克风单喇叭，多连接没有意义 |

---

## 2. 传输层与保活

- 传输：`TCP`，可靠字节流。
- 应用层：自定义帧（长度前缀 + CRC），解决粘包/半包（`net_proto.c::vw_parser_feed`）。
- 字节序：**多字节字段一律大端（Big-Endian）**。
- 心跳：`HEARTBEAT` 每 `CONFIG_VW_HEARTBEAT_PERIOD_S`（默认 3s）发一次；
  超过 `CONFIG_VW_HEARTBEAT_TIMEOUT_S`（默认 12s）没收到任何帧 → 判定链路死亡并重连。

> **心跳必须双向**：下位机只发不收时，会因"最近接收时间"一直不刷新而误判超时，
> 表现为每 2~3 秒连一次断一次。上位机收到心跳后会回一帧空心跳（见 host `pipeline._reply_heartbeat`）。

- 时间戳：`ts_ms` 用 `esp_timer_get_time()/1000`（**开机单调毫秒**），
  不能用 Unix 纪元毫秒——u32 装不下，会溢出。上位机只把它当作相对量。

## 3. 帧格式（字节级）

| 偏移 | 字段 | 长度 | 说明 |
|---|---|---|---|
| 0 | MAGIC | 2 | 固定 `0xAA 0x55` |
| 2 | VERSION | 1 | 协议版本，当前 `0x01` |
| 3 | TYPE | 1 | 见 §3.1 |
| 4 | SEQ | 4 | 大端 u32，每个方向独立递增 |
| 8 | TIMESTAMP_MS | 4 | 大端 u32，开机单调毫秒 |
| 12 | PAYLOAD_LEN | 4 | 载荷长度 N，大端 u32 |
| 16 | PAYLOAD | N | 载荷 |
| 16+N | CRC16 | 2 | CCITT-FALSE，覆盖 `0..15+N` 全部字节 |

**帧总长 = 18 + N 字节。** 解析缓冲 2048 字节，单帧 N 上限受此约束
（音频帧 645 字节、控制帧通常 < 400 字节，余量充足）。

### 3.1 消息类型

| 值 | 名称 | 方向 | 载荷 |
|---|---|---|---|
| 0x01 | `CONTROL` | 双向 | UTF-8 JSON |
| 0x02 | `AUDIO_UP` | 设备 → 上位机 | 音频子帧（§6） |
| 0x03 | `AUDIO_DOWN` | 上位机 → 设备 | 音频子帧（§6） |
| 0x04 | `HEARTBEAT` | 双向 | 空 |
| 0x05 | `ACK` | 双向 | JSON，`{id, code, error?}` |

宏定义：`VW_TYPE_*`（`net_proto.h`）。

### 3.2 CRC16

CCITT-FALSE：多项式 `0x1021`，初值 `0xFFFF`，不取反、不异或输出。
控制帧校验失败直接丢弃（记 `VW_LOG_W`）；音频帧校验失败也丢弃（音频可丢，重传代价更高）。

## 4. 控制帧 JSON

### 4.1 请求（上位机 → 设备）

```json
{ "id": "8f14e45f", "cmd": "volume.set", "params": { "volume": 60 } }
```

### 4.2 应答（设备 → 上位机）

设备在 `reply_control()` 里统一回：

```json
{ "id": "8f14e45f", "cmd": "volume.set", "code": 0, "result": { "volume": 60 } }
```

失败：

```json
{ "id": "8f14e45f", "cmd": "volume.set", "code": 2002, "error": "invalid volume" }
```

- `id` 原样回传，上位机靠它匹配 `_pending`。
- `hello` / `session.*` 是设备**主动发**的事件，没有 `id`，用 `cmd` 区分。

### 4.3 设备支持的命令（收）

| cmd | params | `result` 返回字段 | 副作用 |
|---|---|---|---|
| `config.get` | `{}` | `volume, wake_enable, ack_enable, wifi_ssid, host_ip, host_port` | 无 |
| `config.set` | `volume` `wake_enable` `ack_enable` `host{ip,port}` | 实际生效的 `volume` / `ack_enable` / `host_ip` / `host_port` | 按字段写 NVS；`wake_enable` 立即生效；随后补发一次 `hello` |
| `volume.set` | `volume` (0..100) | `volume` | 写 NVS，立即作用于播放 |
| `wifi.set` | `ssid`（必填）、`password` | 无 | 写 NVS → **500ms 后 reboot** |
| `host.set` | `ip`（必填）、`port` | 无 | 写 NVS → **500ms 后 reboot** |
| `wakeword.set` | `enable`（bool） | 无 | 写 NVS，立即启停唤醒检测 |
| `status.get` | `{}` | `fw, volume, wifi, prov, wake_enable, ack_enable, state` | 无 |
| `prov.start` | `{}` | `prov: true` | **打开蓝牙配网窗口**（已连上时想换 WiFi 用） |
| `reboot` | `{}` | 无 | 回 ACK 后重启 |

说明：

- **`wakeword.set` 只接受 `enable`**，不支持在运行期换唤醒词（换词必须改
  `CONFIG_VW_SR_WAKENET_NAME` 重新烧录，因为模型在 flash 分区里）。
- `state` 取值对应 `app_state_t`：`0=IDLE, 1=ACK_WAIT, 2=CAPTURE, 3=PLAYBACK`。
- 参数非法返回 `code=2002`；未知命令返回 `code=2001`。
- `wifi.set` / `host.set` 要先回 ACK 再重启，中间 `vTaskDelay(500ms)` 留出 TCP 冲刷时间。

### 4.4 设备主动发出的事件

| cmd | params |
|---|---|
| `hello` | `device, fw, audio{rate,bits,ch}, mac, rssi, wakeword, volume` |
| `session.start` | `session_id`(u32)、`need_ack`(bool) |
| `session.end` | `session_id`(u32)、`reason`(`vad` / `max` / `nospeech` / `interrupt`) |

`hello` 示例（连接建立后立即发送；**参数变更后会再发一次**，见下）：

```json
{
  "cmd": "hello",
  "params": {
    "device": "esp32s3",
    "fw": "0.5.0",
    "audio": { "rate": 16000, "bits": 16, "ch": 1 },
    "mac": "28:84:85:45:7B:3C",
    "rssi": -52,
    "wakeword": "wn9_hilexin",
    "volume": 60,
    "wake_enable": true,
    "ack_enable": true
  }
}
```

**重发时机**：`config.set` / `volume.set` / `wakeword.set` 处理成功后，设备会**主动补发一次
`hello`**（在 ACK 之前），上位机设备页靠它立即刷新显示值，不用再点「读取当前配置」。
所以约定：**显示值一律以 `hello` 为准，`config.set` 的 `result` 只用于提示**。

> `mac` / `rssi` / `wakeword` / `volume` 是 v0.7.1 新增，供上位机设备页直接显示，
> 省掉一次 `config.get` 往返。老上位机忽略这些字段即可。

`session.end` 的 `reason`：

| reason | 触发条件 |
|---|---|
| `vad` | 检测到语音后连续静音 `SILENCE_END_FRAMES`(40 帧 = 800ms) |
| `max` | 采集到 `MAX_CAPTURE_FRAMES`(750 帧 = 15s) 上限 |
| `nospeech` | 唤醒后 `WAIT_SPEECH_FRAMES`(150 帧 = 3s) 内没有有效语音 |
| `interrupt` | 播报期间检测到唤醒词（barge-in） |

## 5. 音频帧

音频参数固定：**16 kHz / 16 bit / 单声道 / 小端 PCM**，每帧 20ms = 320 样本 = 640 字节。

载荷 = 子帧头 + 原始 PCM：

| 偏移 | 字段 | 长度 | 说明 |
|---|---|---|---|
| 0 | SESSION_ID | 4 | 大端 u32 |
| 4 | FLAGS | 1 | 见下 |
| 5 | PCM | N*2 | 原始 PCM，默认 640 字节 |

| 位 | 名称 | 方向 | 含义 |
|---|---|---|---|
| bit0 | `AUDIO_FLAG_START` | 双 | 首帧 |
| bit1 | `AUDIO_FLAG_END` | 双 | 末帧 |
| bit2 | `AUDIO_FLAG_HAS_SPEECH` | 上行 | 该帧判定为语音（供上位机参考） |

### 5.1 上行（AUDIO_UP）

- 唤醒后按 20ms 分帧边采边发，首帧带 `START`。
- 结束帧带 `END`；若该帧同时是首帧，则 `START|END` 一起置位。
- **同时补发 `session.end`**，让上位机不必依赖 `END` 位判断（两条路径幂等）。

### 5.2 下行（AUDIO_DOWN）

- 收到 `START` 后开始播放，收到 `END` 且队列播完即结束。
- 播放队列 `PLAY_QUEUE_DEPTH = 40` 帧（≈800ms 抖动缓冲）。
- 入队超时 10ms，队列满时**限频打印告警并丢帧**。

> **上位机必须按实时节奏下发**（每 20ms 一帧，领先播放进度 100~200ms）。
> 一次性灌入整段 TTS 会因队列满而丢帧，听感是"10 秒的话 1 秒念完"。

## 6. 关键时序

### 6.1 唤醒 → 回复词 → 采集 → 播放

```
设备                                          上位机
 │ ── hello ─────────────────────────────────►│
 │ ◄───────────────────────────（无应答，仅记录）│
 │  [WakeNet 命中]                             │
 │ ── session.start{need_ack:true} ──────────►│
 │    进入 APP_ACK_WAIT（最长 ACK_TIMEOUT_MS=4s）│
 │ ◄──────── AUDIO_DOWN(sid, START..END) ─────│ 合成 ack_text 并限速下发
 │  [播放完毕]                                  │
 │    切 APP_CAPTURE                           │
 │ ── AUDIO_UP(sid, START|HAS_SPEECH) ... ───►│
 │ ── AUDIO_UP(sid, END) ────────────────────►│
 │ ── session.end{reason:"vad"} ─────────────►│ STT → LLM → TTS
 │ ◄──────── AUDIO_DOWN(sid, START..END) ─────│
 │  [播放，AEC 参考回采]                        │
```

要点：

- `need_ack=false`（或设备侧 `ack_enable=false`）时跳过 `APP_ACK_WAIT`，直接采集。
- 上位机若未启用回复词或合成失败，**发一个空 END 帧**（无 PCM），设备立即进入采集。
- 设备侧 4s 超时兜底：即使一帧都没收到也会往下走，不会卡死。

### 6.2 播报中打断（barge-in）

```
APP_PLAYBACK ── AEC 参考 = 正在播放的 PCM ──► WakeNet 仍能检测
      │ 命中唤醒词
      ├─► 清空播放队列 + 发 session.end{reason:"interrupt"}
      └─► 重新 session.start（新一轮）
```

### 6.3 配置下发

```
上位机 ── config.set{volume,wake_enable,ack_enable} ─► 设备
上位机 ◄── {id, cmd, code:0, result:{...}} ──────────┘
```

## 7. 蓝牙配网（BLE Provisioning）

取代原 AP 热点方案。原方案的根本缺陷：设备开热点时上位机连不到它的 TCP，
而设备又要去连另一个网段的上位机——`wifi.set` 这条命令**在配网场景下永远发不出去**。
BLE 是点对点链路，不依赖 IP。

### 7.1 触发与退出

| 条件 | 行为 |
|---|---|
| NVS 里**没有凭证**（出厂/擦除后） | 上电立即进入配网 |
| 有凭证但**连续失败 `CONFIG_VW_STA_FAIL_THRESHOLD`(5) 次** | 进入配网 |
| 配网窗口 `CONFIG_VW_PROV_TIMEOUT_S`(300s) 内无有效配置 | **超时退出**，回到 WiFi 重连 |
| 写入配置后连上 WiFi | 推送 `ok` → **关闭蓝牙** → 重启（让新的 host_ip/port 生效） |
| 写入配置后连不上 WiFi | 推送 `fail`，**蓝牙保持开启**，用户可改密码重试 |

### 7.2 GATT 契约

| 项 | UUID | 说明 |
|---|---|---|
| Service | `a0e0f000-1e4d-4f8a-9b6c-1d2e3f4a5b60` | |
| CFG（写） | `a0e0f001-1e4d-4f8a-9b6c-1d2e3f4a5b60` | UTF-8 JSON：`{"ssid","password","host_ip","host_port"}` |
| STATE（读/通知） | `a0e0f002-1e4d-4f8a-9b6c-1d2e3f4a5b60` | UTF-8 JSON：`{"state","error","ip","fw","mac"}` |

`state` 取值：`idle`（已广播待连接）/ `connecting`（正在验证 WiFi）/
`ok`（连上了，`ip` 为设备拿到的地址）/ `fail`（`error` 说明原因）。

广播名：`VoiceWake-XXXX`，**XXXX 是 WiFi MAC 后三字节**，与 `hello.mac` 对得上。
MTU 协商上限 185（配置 JSON 约 140~200 字节，默认 MTU 放不下）。

### 7.3 与控制命令的关系

| 命令 | 配网场景下可用？ | 说明 |
|---|---|---|
| `prov.start` | 已连接时可用 | 让设备重新打开蓝牙配网窗口（换 WiFi 用） |
| `wifi.set` / `host.set` | **配网时不可用** | 需要 TCP；保留给"已连接时手动改凭证"场景（重启生效） |

### 7.4 硬件约束

- BLE 用片内射频，**不占 GPIO**；与 I2S 引脚无冲突。
- WiFi/BLE 共用 2.4G 天线：必须开 `CONFIG_ESP_COEX_SW_COEXIST_ENABLE`，
  且只在配网窗口广播，正常语音链路期间蓝牙是静默的。
- BLE 控制器任务优先级高于音频任务，所以**配网成功后必须真正停广播**（成功路径还会重启）。

## 8. I2S 引脚与音频参数

### 7.1 引脚（`main/Kconfig.projbuild` 可改，**按实际板型核对**）

| 信号 | INMP441（I2S0-RX） | MAX98357A（I2S1-TX） |
|---|---|---|
| BCLK / SCK | `CONFIG_VW_MIC_BCLK_GPIO` = GPIO5 | `CONFIG_VW_AMP_BCLK_GPIO` = GPIO16 |
| WS / LRC | `CONFIG_VW_MIC_WS_GPIO` = GPIO4 | `CONFIG_VW_AMP_LRC_GPIO` = GPIO15 |
| DIN / SD | `CONFIG_VW_MIC_DIN_GPIO` = GPIO6（入） | `CONFIG_VW_AMP_DOUT_GPIO` = GPIO7（出） |

其他接线：

- INMP441：`L/R` 接 GND 或 VDD 决定声道（`CONFIG_VW_MIC_SLOT` 可自动检测）；`VDD` 3.3V。
- MAX98357A：`GAIN` 按需接（悬空 9dB / GND 12dB / VDD 15dB）；`SD_MODE` 接 3.3V 常开。
- 两块模块共用 3.3V 与 GND，**共地不良会出现静止线/串扰**（见 `03_故障排查.md`）。

### 7.2 音频参数

| 项 | 值 | 说明 |
|---|---|---|
| 采样率 | `CONFIG_VW_SAMPLE_RATE` = 16000 | 与上位机 `audio.sample_rate` 必须一致 |
| 位深 | 线上 16 bit | INMP441 侧按 32 bit 槽读，`>>16` 取高 16 位 |
| 声道 | 单声道 | AFE 输入为 2 通道交错 `[mic, ref]` |
| 帧长 | 320 样本 / 640 字节 | `CONFIG_VW_FRAME_MS` = 20 |
| RX 时钟 | **32 bit 槽宽** → BCLK = 64×fS = 1.024 MHz | INMP441 手册要求 fSCK = 64×fWS，16bit 槽只有 32×fS，会表现为"数据减半/漂移" |
| TX 帧格式 | 16 bit 立体声，单声道复制到 L/R | 适配任意 `SD_MODE` 接法，避免只响一边 |
| TX `auto_clear` | **true** | 默认 false 时 DMA 会循环重发最后一段 → 喇叭长鸣 |

## 9. 错误码

协议层错误码（控制应答用，与上位机共用）：

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1001 | 帧头/魔数错误 |
| 1002 | CRC 校验失败 |
| 2001 | 未知命令 |
| 2002 | 参数非法 |
| 3001 | WiFi 未连接 |
| 3002 | 未连接上位机 |
| 4001 | 音频繁忙（正在播放/采集） |
| 5001 | 内部错误 |

固件内部错误码（`vw_err_t`，只出现在串口日志的 `[0xXXXX:名称]` 前缀里）：

| 码段 | 层 | 示例 |
|---|---|---|
| 0x01xx | 通用 | `0x0103 BOOT_FAIL` |
| 0x10xx | 驱动 | `0x1001 I2S_INIT` |
| 0x20xx | 服务 | `0x2003 SR_MODEL_NOT_FOUND` |
| 0x30xx | 通信 | `0x3002 NET_NOT_CONNECTED` |
| 0x40xx | 业务 | `0x4001 SESSION_BUSY` |

## 10. NVS 配置键

命名空间：`vw`（`config_store.c::NVS_NS`）

| 键 | 类型 | 默认值来源 | 说明 |
|---|---|---|---|
| `vol` | blob(u8) | `CONFIG_VW_DEFAULT_VOLUME` = 60 | 0..100 |
| `wake_en` | blob(u8) | 1 | 唤醒开关 |
| `ack_en` | blob(u8) | 1 | 是否等回复词播完再采集 |
| `wifi_ssid` | str(33) | `CONFIG_VW_DEFAULT_WIFI_SSID` | WiFi 名称 |
| `wifi_pass` | str(65) | `CONFIG_VW_DEFAULT_WIFI_PASS` | WiFi 密码 |
| `host_ip` | str(16) | `CONFIG_VW_DEFAULT_HOST_IP` | 上位机 IP |
| `host_port` | blob(u16) | `CONFIG_VW_TCP_PORT` = 8888 | 上位机端口 |

生效顺序：**先套 Kconfig 默认值，再用 NVS 里存在的键覆盖**。
因此 NVS 为空时行为完全由 `menuconfig` 决定。

> 没有 `wake_word` 键：唤醒词来自编译期模型（`CONFIG_VW_SR_WAKENET_NAME`），
> 运行期不可改，所以不持久化。
